\begin{abstract}
Dynamic evaluation, or test-time training, lets a language model keep learning from the text it reads at inference time. The cost is forgetting, as each update can overwrite earlier knowledge, and this is usually treated as a problem. However, the inputs a model receives at inference time often have temporal locality. A book, a long conversation or a code base stays on the same characters, names and vocabulary far longer than an attention window lasts. In a small model, with little room in its weights, locality and forgetting together could be exploited to obtain the behaviour of a cache memory. The weights would hold the recent context beyond the window, and new material would push out old material. We ask whether this cache behaviour arises on its own in a standard transformer that takes plain gradient steps as it reads. We test this with small Pythia models reading PG-19 books. We split the books into short chunks and score each one without the preceding text in context, so any help from earlier chunks must come through the weights. We then compare reading the chunks in order with reading them shuffled, which removes their locality. We find support for the cache hypothesis. The weights hold a memory of the current book beyond the attention window, stored mostly in the MLPs. This memory depends on the order of the input and fades as other books are read, halving within a few thousand tokens. As expected, it competes with general knowledge for the same weights. Knowledge of the same domain is largely preserved, while out-of-domain text is partly forgotten, and a stronger cache is hard to get without more of this forgetting. Decoupling the two could give a stronger cache and a better use of temporal locality, reducing the model size required for a given performance.
\end{abstract}

\section{Introduction}

What a language model reads at inference time has temporal locality: a book keeps its characters, places and turns of phrase for hundreds of thousands of tokens, and so do a long conversation or a code base.
Computer memory hierarchies exploit this property with a small cache that holds recently used data and lets older data be pushed out \cite{denning1968working}.
A transformer has such a cache in its attention window, but the window is short and everything before it is lost.

A model that keeps updating its weights while it reads could keep a memory of the recent text in those weights, beyond the window.
Dynamic evaluation \cite{krause2018dynamic,krause2019dynamic,rannentriki2024revisiting} and test-time training \cite{feng2026inplace,bansal2026lets,tandon2025endtoend} do this and report lower loss.
Less is known about what the updated weights hold.
If they act as a cache, three things should be true.
The benefit should depend on \emph{locality}: it should be larger when the input stays on the same material than when the same text arrives in a random order.
New material should push out old material, which we call \emph{eviction}.
And the cache should not destroy the knowledge the model already had; loss of that knowledge we call \emph{forgetting}, the catastrophic interference of sequential training \cite{mccloskey1989catastrophic}.

We test this with small Pythia models \cite{biderman2023pythia} reading PG-19 books \cite{rae2020compressive}.
Each 256-token chunk is scored on its own, without the previous chunks in the context, so anything that helps from further back must come through the weights; after scoring a chunk, the model takes one update step on it.
We ask whether online learning helps more when the input has locality than when it is shuffled, whether it evicts old content like a cache, what it costs in general knowledge, where in the network the memory lives and whether a knob sets its size, and whether it matters more in small models or can replace a larger one.

Contributions, one per group of findings:
\begin{itemize}
\item a local memory beyond the window, tied to the current book and more than a token-count cache (Section~\ref{sec:local});
\item its location: the MLPs, where updating only them gives more cache and more forgetting (Section~\ref{sec:where});
\item the gain as a function of the locality of the input (Section~\ref{sec:levels});
\item eviction and forgetting measured with frozen snapshots of the learner (Sections~\ref{sec:eviction} and~\ref{sec:forgetting});
\item update rules across sizes, and a trade-off between cache and forgetting (Sections~\ref{sec:rules} and~\ref{sec:tradeoff});
\item long books: what online learning is worth against a larger model (Section~\ref{sec:long}).
\end{itemize}

\section{Related work}

\paragraph{Dynamic evaluation.}
Krause et al.\ \cite{krause2018dynamic,krause2019dynamic} adapt a language model to the sequence it predicts with gradient steps at test time; Rannen-Triki et al.\ \cite{rannentriki2024revisiting} revisit this for larger models and describe it as memory in the weights.
We use the same protocol (score, then update) and ask what the updated weights remember, for how long, where, and at what cost.

\paragraph{Cache language models.}
Recent words \cite{kuhn1990cache} or recent hidden states \cite{grave2017improving} can be mixed into a model's prediction; our unigram cache is the simplest such baseline.

\paragraph{Test-time training.}
Test-time training adapts a model to each test input with a self-supervised loss \cite{sun2020test}.
For language models, In-Place TTT \cite{feng2026inplace} updates the final projection of the MLP blocks, qTTT \cite{bansal2026lets} the query projections, and TTT-E2E \cite{tandon2025endtoend} meta-learns a model for test-time training.
That the MLPs hold most of the memory agrees with In-Place TTT's choice and with feed-forward layers as key-value memories \cite{geva2021transformer}.

\paragraph{Fast weights.}
Fast weights hold short-term memory on top of slow weights \cite{hinton1987using,schmidhuber1992learning,ba2016using,schlag2021linear}; we do not test a separate fast part here (Section~\ref{sec:future}).

\section{Setup}\label{sec:setup}

\paragraph{Models.}
Pythia-14M, 31M and 70M \cite{biderman2023pythia} (14.07M, 30.49M and 70.43M parameters, 6 layers each, same tokenizer), in float32 on CPU, seed 0.

\paragraph{Data.}
All books are from PG-19 \cite{rae2020compressive}.
The \emph{main set} is 25 test books, each cut into 78 chunks of 256 tokens (its first 19{,}968 tokens).
The \emph{long set} is 5 test books of 100k tokens (390 chunks each), and the \emph{very long set} is 4 test books of 200k tokens (781 chunks each); all 5 long books and 2 of the 4 very long books are also in the main set, cut there to their first 78 chunks.
Learning rates are picked on \emph{val-pick}, 10 PG-19 validation books of 78 chunks each.
Two held-out sets are never trained on: 76 chunks of WikiText-103's test split \cite{merity2017pointer}, detokenized, and 6 other validation books of 15 chunks each.
Pythia was trained on the Pile \cite{gao2020pile}, whose PG-19 component has 28{,}602 documents \cite{biderman2022datasheet}, the size of PG-19's training split; the test books are therefore very likely not in Pythia's training data, although the authors do not say so and other copies of the books were not checked.

\paragraph{Protocol.}
Each chunk is scored on its own, without earlier chunks in the context.
Online, after scoring a chunk the model takes one update step on the chunk's mean loss, so every token is predicted before it is trained on.
The frozen model reads the same chunks without updates.

\paragraph{Update rules and parameter subsets.}
\emph{Plain SGD} uses no momentum or weight decay.
\emph{Adam} \cite{kingma2015adam} updates all parameters with a fresh state at the start of each stream.
\emph{Normalized SGD} moves every tensor by the same relative amount per step, $W \leftarrow W - \eta\, \lVert W\rVert\, g / \lVert g\rVert$.
With plain SGD, some runs update only part of Pythia-14M: the output embedding, everything but the output embedding, the MLPs of all layers, the attention of all layers, or one layer's MLP.

\paragraph{Stream orders.}
The main set's chunks are read in four orders: book after book ($K=1$), 5 books interleaved chunk by chunk ($K=5$), all 25 interleaved ($K=25$), and one random order (shuffled).
The long and very long sets are read book after book.

\paragraph{Snapshot probes.}
To see what the weights hold at a given point, we copy them and score other text with the copy frozen, while the learner continues.
Snapshots are taken every 40 chunks and scored on the held-out sets.
For eviction (Section~\ref{sec:eviction}), each of 20 main books A is split into a first half A1 (40 chunks) and a second half A2 (38 chunks); the learner reads A1, then $I$ tokens of PG-19 validation books, and a snapshot scores A2 and the same span C2 of a control book C that it never read.

\paragraph{Learning rates.}
Each learning rate is the value with the lowest mean online loss on val-pick, from a grid of $1$ and $3$ times powers of ten.
The grid is extended until both neighbours of the best value have been tried, so every pick lies inside its grid.
Each parameter subset, update rule and size has its own pick.

\paragraph{Metrics.}
The \emph{gain} measures how much online learning helps: the frozen loss minus the online loss on the same tokens, in nats/token, against each model's own frozen loss.
\emph{Distance bins} sort tokens by how far back the same token id last occurred: in the same chunk (visible to attention), in an earlier chunk less than 1k, 1k to 10k, 10k to 100k or at least 100k tokens back, or never; the 1000 most frequent ids are left out of the earlier-chunk bins.
Earlier-chunk bins are split by whether that occurrence was in the same book or an earlier one.
\emph{Locality} measures how much of the gain needs the order of the text: the gain in reading order minus the gain on the same chunks shuffled.
The \emph{memory of A} measures what the snapshot still knows about book A beyond general adaptation: its gain on A2 minus its gain on C2.
\emph{Forgetting} measures lost general knowledge: a snapshot's loss on a held-out set minus the pretrained model's, averaged over the snapshots in the second half of the stream (positive means knowledge lost).
The \emph{exchange rate} measures what a run gains per unit of knowledge it loses: its gain on the stream divided by its WikiText forgetting.

\paragraph{Error bars.}
Means are over tokens.
Standard errors (SE) are over books, from per-book means or, when two runs read the same chunks, from paired per-book differences; books with fewer than 50 tokens in a bin are left out.
For forgetting, SE are over the WikiText chunks or the 6 held-out books.
A $\dagger$ marks a value under 2 SE, which we do not treat as a difference.

\section{Results}

\subsection{A memory beyond the window, and it is local}\label{sec:local}

If the updated weights hold a memory of the text, tokens seen recently in an earlier chunk should be predicted better, and the benefit should depend on the order of the chunks.
We bin tokens by the distance to their previous occurrence and compare reading in order with reading the same chunks shuffled.

With plain SGD at lr $10^{-4}$, Pythia-14M gains \gainInOrderAllPM{} nats/token over its frozen loss of \frozenLossMain{} (Table~\ref{tab:distance}).
The gain falls with distance: \gainInOrderOneKPM{} for rare tokens last seen less than 1k tokens back, \gainInOrderTenKPM{} between 1k and 10k, and \gainInOrderHundredKPM{} between 10k and 100k.
Tokens never seen before lose \gainInOrderNeverPM{}, and tokens repeated within their own chunk lose \gainInOrderSameChunkPM{}.
Within a book the gain grows from \posGainFirstPM{} in its first 1k tokens to \posGainLastPM{} in its last 1k, while the shuffled learner's gain stays between \posShuffledMin{} and \posShuffledMax{} (Figure~\ref{fig:distance}b).

Shuffling keeps \shuffledShareAll{} of the overall gain, but only \shuffledShareOneK{} less than 1k tokens back and \shuffledShareTenK{} between 1k and 10k (locality \localityOneKPM{} and \localityTenKPM{}).
Most of the overall gain is therefore adaptation to PG-19 text in general, and most of the long-range gain needs the order.

\paragraph{The current book.}
A token may be predicted better because it was seen recently, or because it belongs to the book being read.
Splitting the earlier-chunk bins by book separates the two (Table~\ref{tab:samebook}).
Between 1k and 10k tokens back, the locality is \localityTenKSamePM{} for tokens last seen in the same book and \localityTenKEarlierPM{} for tokens last seen in an earlier book.
Between 10k and 100k tokens back, same-book tokens keep \localityHundredKSamePM{} of locality and earlier-book tokens have none (\localityHundredKEarlierPM{}).
The memory is tied mostly to the current book, although distance still matters within it.

\paragraph{More than a count cache.}
A cache of recent token counts mixed into the frozen model ($p = 0.95\, p_\text{model} + 0.05\, p_\text{cache}$, counts halving every 1k tokens) is the simplest way to use the recent past.
It is the better copier less than 1k tokens back (\gainUnigramOneKPM{} against \gainInOrderOneK{}), but from 1k tokens on online learning gains more (\gainInOrderTenK{} against \gainUnigramTenKPM{} between 1k and 10k; paired difference \inOrderMinusUnigramTenKPM{}), and \inOrderMinusUnigramAllPM{} more overall (Table~\ref{tab:distance}).

\subsection{Where the memory lives}\label{sec:where}

If the memory sits in particular weights, updating only those should keep it.
We update one part of Pythia-14M at a time, each part at its own learning rate (Table~\ref{tab:layers}).

Freezing the output embedding costs little (\minusFullNoOutputAllPM{} overall against all parameters).
The output embedding alone is a short-range cache: \gainOutputOneKPM{} less than 1k tokens back but \gainOutputTenKSamePM{} between 1k and 10k (same book), with the largest loss on never-seen tokens (\gainOutputNeverPM{}).
Attention alone keeps less of the long-range gain (\gainAttentionTenKSamePM{} between 1k and 10k, same book).
Updating only the MLPs (lr $3\times10^{-4}$) gains more than updating all parameters (lr $10^{-4}$): \gainMlpOneKPM{} against \gainInOrderOneK{} less than 1k tokens back (paired difference \minusFullMlpOneKPM{}) and \gainMlpAllPM{} against \gainInOrderAll{} overall (\minusFullMlpAllPM{}).

One layer's MLP alone keeps between \layerShareOneKMin{} and \layerShareOneKMax{} of the full learner's gain less than 1k tokens back, and between \layerShareTenKMin{} and \layerShareTenKMax{} between 1k and 10k (same book); every single layer is below the full learner there (Figure~\ref{fig:layers}a).
The strongest is layer \layerBest{} (\layerBestOneKPM{}, paired difference with all parameters \layerBestMinusFullPM{}), and the last layer is the weakest (\layerLastOneKPM{}).

\paragraph{MLPs only against all parameters.}
A larger gain could come from a stronger cache or from better general adaptation, and a stronger cache might cost more general knowledge.
We read the shuffled stream with both learners and probe both with snapshots (Table~\ref{tab:mlpfull}).
Updating only the MLPs gives more locality: \mvfMlpLocOneKPM{} against \mvfFullLocOneKPM{} less than 1k tokens back (paired difference \mvfDiffLocOneKPM{}) and \mvfMlpLocTenKPM{} against \mvfFullLocTenKPM{} between 1k and 10k, same book (\mvfDiffLocTenKPM{}).
Shuffled, it gains slightly less overall (\mvfDiffShuffledAllPM{}).
It also forgets more: WikiText forgetting is \mvfMlpWikiPM{} against \mvfFullWikiPM{} (paired \mvfDiffWikiPM{}), and the held-out books lose \mvfDiffBooksPM{} more (paired), although neither run's own value on them is beyond 2 SE.
Its exchange rate is lower: \mvfMlpExchange{} against \mvfFullExchange{} in order, \mvfMlpExchangeSh{} against \mvfFullExchangeSh{} shuffled.

The two learners use different learning rates, each its own val-pick (val-pick loss \valPickMlp{} for the MLPs at $3\times10^{-4}$ and \valPickAll{} for all parameters at $10^{-4}$).
All parameters at $3\times10^{-4}$ is already worse on val-pick (\valPickAllHigh{}).
A possible reason, not tested: with plain SGD at 14M, attention takes \shareAttnFourteen{} of the squared update norm and the MLPs \shareMlpFourteen{} (Section~\ref{sec:rules}), which may limit the step the full learner can use.

\subsection{Locality as a variable}\label{sec:levels}

A cache should help more the longer the input stays on the same material.
We read the same chunks with more and more books interleaved, and the long books in order (Figure~\ref{fig:layers}b).

With plain SGD on all parameters at lr $10^{-4}$, the gain falls at every step: \levelLongPM{} on the long books, \levelKOnePM{} with $K=1$, \levelKFivePM{} with $K=5$, \levelKTwentyFivePM{} with $K=25$ and \levelShuffledPM{} shuffled.
On the main set the paired drops are \dropKFivePM{} from $K=1$ to $K=5$, \dropKTwentyFivePM{} from $K=5$ to $K=25$ and \dropShuffledPM{} from $K=25$ to shuffled; interleaving only 5 books removes most of the in-order advantage.
The long books are other books than the main set, so the step from them to $K=1$ is not paired.

\subsection{Eviction}\label{sec:eviction}

If online learning acts as a cache, reading other text should push a book out of memory.
We let the model read the first half of a book, then other books, and check with a frozen snapshot how well it still predicts the book's second half, compared with a book it never read (Figure~\ref{fig:eviction}).

With plain SGD on all parameters at lr $10^{-4}$, the memory of A is \memoryZeroPM{} right after A1.
It halves after about \evictHalfLife{} tokens of other books and then declines slowly: \memoryTenKPM{} after 10k tokens, \memoryHundredKPM{} after 100k and \memoryThreeHundredKPM{} after 300k.
The snapshots never gain on the control book (\gainCZeroPM{} right after A1, between \gainCMin{} and \gainCMax{} later), so the decline is the loss of A rather than general adaptation catching up.
The memory is mostly about tokens that occurred in A1: rare tokens of A2 whose id occurs in A1 carry \memoryRareInPM{} after A1, and other rare tokens \memoryRareNotInPM{}; the former halve after about \evictHalfLifeRare{} tokens.
A power law in $I$ fits the memory better than an exponential with a floor ($\chi^2$ \fitChiPower{} against \fitChiExp{}, with 4 degrees of freedom each), but the 7 points share the same 20 books, so this only ranks the two shapes.

\subsection{Forgetting}\label{sec:forgetting}

A cache should leave the rest of memory intact.
We score frozen snapshots of the learner on text it never reads: WikiText, outside the domain, and unseen PG-19 books, inside it (Table~\ref{tab:forgetting}).

With plain SGD at lr $10^{-4}$, Pythia-14M reading the main set in order forgets \forgetWikiKOnePM{} nats/token on WikiText (pretrained loss \frozenWiki{}), about \wikiOverGainKOne{} times its gain on the stream (exchange rate \exchangeKOne{}).
On the held-out PG-19 books it loses nothing (\forgetBooksKOnePM{}).
The shuffled learner forgets less on WikiText (\forgetWikiShuffledPM{}) and improves on the unseen books (\forgetBooksShuffledPM{}): the part of the gain that survives shuffling is adaptation to PG-19 text, and it carries over to unseen books.
Reading in order forgets more than shuffled on both sets (shuffled $-$ in order: \shMinusKOneWikiPM{} on WikiText, \shMinusKOneBooksPM{} on the books), at about the same exchange rate (\exchangeKOne{} and \exchangeShuffled{}).
On the very long set (800k tokens), WikiText forgetting averages \veryLongWikiBookOne{} over the snapshots taken in the first book and \veryLongWikiBookTwo{}, \veryLongWikiBookThree{} and \veryLongWikiBookFour{} in the next three: it levels off after the first book.
There the held-out books also lose a little (\forgetBooksVeryLongPM{}).

\subsection{Update rules and model size}\label{sec:rules}

With plain SGD, a learning rate small enough for some weights may be too small for others, and the balance changes with model size.
We log the size of each update and compare three update rules at three sizes, each with its own learning rate (Table~\ref{tab:rules}, Figure~\ref{fig:rules}).

Over the first 40 chunks, plain SGD at each size's pick moves the MLP weights by \relMlpFourteen{} of their norm per step at 14M, \relMlpThirtyOne{} at 31M and \relMlpSeventy{} at 70M, about \mlpStepRatio{} times less at 70M than at 14M; at 70M attention takes \shareAttnSeventy{} of the squared update norm and the MLPs \shareMlpSeventy{}.
With plain SGD, Pythia-70M gains \rGainSgdSeventyPM{} and has almost no locality (\rLocOneKSgdSeventyPM{} less than 1k tokens back).
Normalized SGD more than doubles 70M's gain (\rGainNsgdSeventyPM{}; paired difference \nsgdMinusSgdGainSeventyPM{}) and gives it locality (\rLocOneKNsgdSeventyPM{}), still far less than at 14M and 31M under the same rule (\rLocOneKNsgdFourteenPM{} and \rLocOneKNsgdThirtyOnePM{}), which are the largest of any rule.
Adam has no cache at any size: its locality less than 1k tokens back is \rLocOneKAdamFourteenPM{} at 14M, \rLocOneKAdamThirtyOnePM{} at 31M and \rLocOneKAdamSeventyPM{} at 70M.

From 14M to 31M, plain SGD's locality does not change beyond noise (31M $-$ 14M: \locDiffThirtyOneFourteenOneKPM{} less than 1k tokens back, \locDiffThirtyOneFourteenAllPM{} overall; SE unpaired across models); it falls at 70M under every rule.
The smaller model does not pay more general knowledge per nat of gain: the exchange rate at 14M is \rExchangeSgdFourteen{}, \rExchangeAdamFourteen{} and \rExchangeNsgdFourteen{} (plain SGD, Adam, normalized SGD), against \rExchangeSgdThirtyOne{}, \rExchangeAdamThirtyOne{} and \rExchangeNsgdThirtyOne{} at 31M.
At 70M it is \rExchangeSgdSeventy{}, \rExchangeAdamSeventy{} and \rExchangeNsgdSeventy{}, with much smaller gains.

\subsection{A trade-off between cache and general knowledge}\label{sec:tradeoff}

If the cache and general knowledge share the same weights, filling one should erode the other.
We place every run with snapshots on two axes: how much cache it has (locality less than 1k tokens back) and how much WikiText it forgets (Figure~\ref{fig:tradeoff}).

Within 14M the order is the same on both axes: Adam (\rLocOneKAdamFourteen{}, \rWikiAdamFourteen{}), plain SGD on all parameters (\rLocOneKSgdFourteen{}, \rWikiSgdFourteen{}), plain SGD on the MLPs only (\mvfMlpLocOneK{}, \mvfMlpWiki{}) and normalized SGD (\rLocOneKNsgdFourteen{}, \rWikiNsgdFourteen{}).
Within 31M the same holds for Adam, plain SGD and normalized SGD.
At 70M plain SGD and normalized SGD follow it, but Adam forgets more than both (\rWikiAdamSeventyPM{}) with negative locality.
Across sizes the points do not lie on one curve: at 70M every rule forgets far less for a given locality.
With ten points, one seed and one model family, this is a consistent ordering within the 14M and 31M settings we tried, not a law, and it does not hold for Adam at 70M.

\subsection{Long books and model size}\label{sec:long}

A cache is worth more the longer the material stays the same, and a small model might use it to approach a larger one.
We let Pythia-14M and Pythia-31M learn online on books of 200k tokens and compare them with frozen 14M, 31M and 70M (Table~\ref{tab:verylong}, Figure~\ref{fig:verylong}).

With plain SGD at lr $10^{-4}$, Pythia-14M gains \vlGainOnlineFourteenPM{} over its frozen loss and closes \gapClosedFourteen{} of the gap to a frozen Pythia-31M.

\section{Discussion}

\paragraph{Does online learning help more with locality than with random input?}
Yes: the gain from more than 1k tokens back mostly disappears when the chunks are shuffled, and the overall gain falls at every step from long books to shuffled chunks (Sections~\ref{sec:local} and~\ref{sec:levels}).

\paragraph{Does it evict like a cache?}
Yes for the memory of a specific book: it halves after a few thousand tokens of other books, with a long tail (Section~\ref{sec:eviction}).
Unlike a cache, filling it overwrites general knowledge outside the domain: WikiText forgetting is about twice the gain on the stream, and within 14M and 31M a stronger cache forgets more (Sections~\ref{sec:forgetting} and~\ref{sec:tradeoff}).

\paragraph{Is the effect larger in small models?}
Not between 14M and 31M: locality does not change beyond noise, and 14M does not pay more forgetting per nat of gain.
70M has less cache, but how much depends on the update rule and the step size it allows (Section~\ref{sec:rules}).

\paragraph{Is there a knob?}
Partly: the parameter subset and the update rule move the size of the cache, but within 14M and 31M every setting we tried moves cache and forgetting together (Section~\ref{sec:tradeoff}).
No knob tested here separates the cache from general knowledge.

\paragraph{Can a small model with online learning replace a larger one?}
Not at these sizes: on long books online learning is worth about half the step from 14M to 31M, but 31M gains as much from it (Section~\ref{sec:long}).
Baselines with the full context window and with matched compute are still missing.

\paragraph{Does it resemble human memory?}
Only suggestively, and we did not test it directly.
Most of a book's memory is on the specific tokens seen (\memoryRareIn{} for rare tokens of A1, against \memoryRareNotIn{} for other rare tokens), which resembles episodic memory, while the gain that survives shuffling transfers to unseen books, which resembles semantic memory.
Eviction is fast at first and slow later, closer to a power law than to an exponential.

\section{Limitations}

\begin{itemize}
\item \textbf{One seed.} Error bars are across books, not across models or runs.
\item \textbf{Three sizes of one family.} Pythia-14M, 31M and 70M only.
\item \textbf{One kind of data.} PG-19 books only; WikiText is the only out-of-domain text, and forgetting is measured on 76 WikiText chunks and 6 books.
\item \textbf{No full-context baseline.} Chunks of 256 tokens are scored without earlier context; a model with its full context window would see more of the recent past through attention.
\item \textbf{Learning rates.} Rates are picked on mean validation loss, not on locality, and different subsets and sizes use different rates, so comparisons across them mix in the rate.
\item \textbf{Wall time is not compute.} We did not measure compute; online runs update after every chunk, frozen runs do not.
\item \textbf{Overlapping sets.} All 5 long books and 2 of the 4 very long books are also in the main set.
\end{itemize}

\section{Future work}\label{sec:future}

\begin{itemize}
\item A separate fast cache part on top of a frozen or slowly learning model, with a fallback to the frozen model when the cache does not help.
\item Capacity: many books interleaved at once, and the size of the adapted part against the eviction half-life.
\item Why Adam removes the cache: ablate its momentum and its per-weight normalization.
\item Baselines with the full context window and with matched compute.
\item More seeds (PolyPythias \cite{vanderwal2025polypythias}) and larger models.
\item Direct memory tests: savings on re-reading, interference between similar books, spacing, and planted facts.
\end{itemize}

\section{Conclusion}

A small language model that takes one update step on each chunk it reads gains a memory of its current context beyond its attention window.
The memory behaves like a cache in three ways: it depends on the order of the input (\shuffledShareOneK{} of the gain less than 1k tokens back survives shuffling), it is tied to the current book, and other books evict it, halving it after about \evictHalfLife{} tokens.
It differs from a cache in where it is stored: it shares weights with general knowledge, and filling it costs knowledge outside the domain, about \wikiOverGainKOne{} nats of WikiText loss per nat gained.
Which weights are updated and which update rule is used change how much cache a model gets, but within 14M and 31M not the trade-off between cache and forgetting.
Between 14M and 31M, size does not change this picture, and on long books online learning closes \gapClosedFourteen{} of the gap to the larger model without replacing it.
