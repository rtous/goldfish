\title{A Cache in the Weights? Dynamic Evaluation and Temporal Locality in Small Language Models}
\author{Ruben Tous\\ \small{\textit{Universitat Politècnica de Catalunya, Barcelona, Spain}}}
\date{Draft, \today}

\begin{document}
\maketitle

\begin{abstract}
Dynamic evaluation and test-time training let a language model keep learning from the text it reads at inference time. The cost is forgetting, as each update can overwrite earlier knowledge, and this is usually treated as a problem. However, the inputs a model receives at inference time (e.g. a book or a code base) often show some degree of temporal locality, i.e. recently seen content is likely to be seen again. In a small model, with little room in its weights, locality could make forgetting useful, so that together they could be exploited to obtain the behaviour of a cache memory. The weights would hold the recent context beyond the window, and new material would push out old material. We ask whether this cache behaviour arises on its own in a standard transformer that takes plain gradient steps as it reads. We test this with small Pythia models reading PG-19 books. We split the books into short chunks and score each one without the preceding text in context, so any help from earlier chunks must come through the weights. We then compare reading the chunks in order with reading them shuffled, which removes their locality. We find support for the cache hypothesis. The weights hold a memory of the current book beyond the attention window, stored mostly in the MLPs. This memory depends on the order of the input and fades as other books are read, halving within a few thousand tokens. As expected, it competes with general knowledge for the same weights. Knowledge of the same domain is largely preserved, while out-of-domain text is partly forgotten, and a stronger cache is hard to get without more of this forgetting. Decoupling the two could give a stronger cache and a better use of temporal locality, reducing the model size required for a given performance.
\end{abstract}

\section{Introduction}

Language models store in their parameters a vast amount of knowledge, most of which is irrelevant to any particular input they process.
Small models are cheaper to run and can be deployed on memory-constrained devices, but their limited capacity restricts how much knowledge and context they can retain. % TODO: citation for small / on-device models
Yet what a model reads at inference time has temporal locality, i.e.\ recently seen content is likely to be seen again: a book keeps its characters, places and turns of phrase for hundreds of thousands of tokens, and so do a long conversation or a code base, far longer than an attention window lasts.
Computer memory hierarchies exploit this property with a small cache that holds recently used data and lets older data be pushed out, allowing a small memory to serve a workload as though it were a large one \cite{denning1968working}.
By analogy, a small model whose parameters cached its current context, instead of permanently holding everything it might ever need, could perform on that context comparably to a larger model.

A transformer already has such a cache in its attention window, but the window is short and everything before it is lost.
Dynamic evaluation \cite{krause2018dynamic,krause2019dynamic,rannentriki2024revisiting} and test-time training \cite{feng2026inplace,bansal2026lets,tandon2025endtoend} let a language model keep learning from the text it reads at inference time, adapting its weights to the current input distribution and thus predicting what follows better than a frozen model.
The cost is forgetting: each update can overwrite earlier knowledge, the catastrophic interference of sequential training \cite{mccloskey1989catastrophic}, and this is usually treated as a problem.
In a small model, with little room in its weights, locality and a forgetting that spares recent content could together give the behaviour of a cache memory: the weights would hold the recent context beyond the window, and new material would push out old material.

We ask whether this cache behaviour arises on its own in a standard transformer that takes plain gradient steps as it reads.
If it does, three things should be true.
The benefit should depend on \emph{locality}: it should be larger when the input stays on the same material than when the same text arrives in a random order.
New material should push out old material, which we call \emph{eviction}; this is the useful side of forgetting.
And the cache should leave the knowledge the model already had largely intact; we call the loss of that general knowledge, the harmful side, simply \emph{forgetting} from now on.

We test this with small Pythia models \cite{biderman2023pythia} reading PG-19 books \cite{rae2020compressive}.
We split the books into chunks of 256 tokens and score each one on its own, without the previous chunks in the context, so anything that helps from further back must come through the weights.
After scoring a chunk, the model takes one update step on it.
We compare reading the chunks in order with reading them shuffled, which removes their locality.
Beyond the three predictions above, we study where in the network the memory lives, whether a knob sets its size, and whether it matters more in small models or can replace a larger one.

Our contributions are as follows.
\begin{itemize}
\item We measure the reach of the memory and its dependence on input locality, and compare it with a token-count cache (Sections~\ref{sec:local} and~\ref{sec:levels}).
\item We locate where in the network the memory is stored (Section~\ref{sec:where}).
\item We measure how fast other text evicts the memory, and how much general knowledge, inside and outside the domain, is forgotten (Sections~\ref{sec:eviction} and~\ref{sec:forgetting}).
\item We study how the update rule and the model size affect the cache and its forgetting, and the trade-off between the two (Sections~\ref{sec:rules} and~\ref{sec:tradeoff}).
\item We assess what dynamic evaluation is worth against a larger frozen model on long books (Section~\ref{sec:long}).
\end{itemize}

The long-term objective of this line of work is to determine whether such a cache can reduce the model size required for a given level of performance.
The present study is a first step towards that objective, examining whether cache behaviour emerges in a standard transformer under dynamic evaluation and at what cost to general knowledge.


\section{Related work}

This work builds on \emph{temporal locality}, the tendency of recently observed content to recur, and on the possibility that a small model could exploit it by caching its current context in its weights through online learning.
Temporal locality is a property of the input; exploiting it requires a recency bias in the model, which here resides in the weights rather than, as usually studied in language models, in the context window \cite{zhao2021calibrate}.
We review four related lines of research from this perspective.

\paragraph{Cache language models.}
Memory hierarchies exploit temporal locality with a small cache that retains recently used data, allowing a small memory to serve a workload almost as well as a large one \cite{denning1968working}.
Text exhibits the same property: a word that has occurred in a document is far more likely to recur than its corpus frequency predicts \cite{church2000empirical}, and source code is similarly repetitive within a file or module \cite{tu2014localness}.
Cache language models exploit this by interpolating the model's prediction with a distribution estimated from the recent history \cite{kuhn1990cache,jelinek1991dynamic}.
Neural variants store recent hidden states instead of word counts \cite{grave2017improving,khandelwal2020generalization}, and several transformer architectures extend the attention window with recurrent, compressed or external memories \cite{dai2019transformerxl,rae2020compressive,wu2022memorizing,bulatov2022recurrent}.
In all of these the past is held in activations or in a separate store, and the parameters remain fixed.
We instead restrict the context so that the past can only be held in the parameters, and ask whether they behave as a cache; a token-count cache serves as a baseline (Section~\ref{sec:local}).

\paragraph{Dynamic evaluation.}
Dynamic evaluation applies online learning to a trained model during evaluation: the parameters are updated by gradient descent on the portion of the sequence already observed, so that each token is predicted before it is trained on.
It was first applied to recurrent language models \cite{mikolov2010recurrent,graves2013generating} and studied systematically by Krause et al.\ \cite{krause2018dynamic,krause2019dynamic}, who motivate it by the recurrence of patterns within a sequence and favour recent history through a decay towards the trained weights.
Rannen-Triki et al.\ \cite{rannentriki2024revisiting} interpret it as a memory in the weights complementary to the context window, reset the weights at book boundaries, and show that under distribution shift a smaller model or context with online learning can offer a better trade-off between compute and loss than a larger static model.
That dynamic evaluation benefits from temporal locality is thus the premise of this literature.
Our contribution is to quantify it, comparing the same text in order and shuffled and decomposing the gain by the distance and book of each token's previous occurrence (Sections~\ref{sec:local} and~\ref{sec:levels}).
We use neither decay nor resets, so that eviction can be measured directly (Section~\ref{sec:eviction}), and we compare against model size rather than compute (Section~\ref{sec:long}).

\paragraph{Test-time training and fast weights.}
Test-time training adapts a model to each test instance through a self-supervised objective \cite{sun2020test} and has inspired sequence layers and memory modules that learn as they read \cite{sun2024learning,behrouz2024titans}.
Recent methods for transformer language models differ mainly in the parameters they update: the output projections of the MLP blocks \cite{feng2026inplace}, the query projections of attention \cite{bansal2026lets}, or the MLP weights of a model meta-trained for test-time adaptation \cite{tandon2025endtoend}.
They descend from fast weights, rapidly changing parameters that provide short-term memory on top of slow ones \cite{hinton1987using,schmidhuber1992learning,ba2016using,clark2022meta}.
These methods mostly target long contexts, fix by design which parameters adapt and how quickly the memory fades, and are evaluated by the reduction in loss.
We study instead an unmodified pretrained model under plain gradient steps, and ask where the memory forms (Section~\ref{sec:where}), how the update rule and model size shape it (Section~\ref{sec:rules}), and how long it persists, with a view to techniques that exploit temporal locality in small models.

\paragraph{Forgetting.}
When one set of parameters serves both short- and long-term memory, new learning interferes with existing knowledge.
This catastrophic interference was first documented in connectionist networks trained sequentially \cite{mccloskey1989catastrophic,french1999catastrophic} and has motivated methods that protect the parameters most relevant to earlier tasks \cite{kirkpatrick2017overcoming}.
Large language models lose general capabilities during continual fine-tuning \cite{luo2023empirical}, models updated by dynamic evaluation degrade on older text \cite{lazaridou2021mind}, and knowledge acquired during pretraining decays as a power law of subsequent training steps \cite{chang2024how}.
Much of this knowledge appears to reside in the feed-forward layers \cite{geva2021transformer,meng2022locating}.
Forgetting may also be adaptive, reflecting the decreasing probability that an item will be needed again \cite{anderson1991reflections}; a cache relies on the same assumption, and its limited capacity can follow a changing context only by evicting what is no longer in use.
We therefore measure both the eviction of a book's memory and the loss of general knowledge in the same runs (Sections~\ref{sec:eviction}, \ref{sec:forgetting} and~\ref{sec:tradeoff}).

\section{Setup}\label{sec:setup}

Every experiment in this paper has the same structure.
A model reads an \emph{input stream}: a single, ordered sequence of text that it reads once, from beginning to end, in consecutive chunks of 256 tokens, as a language model reads text during inference.
Attention covers only the current chunk, so whatever the model can use from earlier parts of the stream must be carried in its weights.
Under dynamic evaluation the model updates those weights as it reads; the frozen pretrained model reading the same stream without updates is the reference.
The experiments differ in the streams they use, which vary in length and in how often their content recurs, and in what is measured on the updated weights along the way.
We first describe the streams and why each is needed, then how the learner reads them and what we measure.

\subsection{Models}

We use Pythia-14M, 31M and 70M \cite{biderman2023pythia}, with 14.07M, 30.49M and 70.43M parameters respectively; all three have 6 layers and share the same tokenizer, and all runs use float32 on CPU with seed 0.

\subsection{Input streams}

All streams are built from books of PG-19 \cite{rae2020compressive}.
Each book is tokenized on its own and cut into non-overlapping chunks of 256 tokens, the remainder dropped, so that no chunk spans two books.
A stream is a set of such chunks placed in a fixed reading order.
It is read without interruption: the learner starts from the pretrained weights at the beginning of the stream, and its weights are not reset between books, so a book is read with whatever the weights retain from the books before it.

Different questions call for different streams, and we use four kinds, summarized in Table~\ref{tab:streams}.

\paragraph{Main streams: the same text in different orders.}
The central question is whether the learner exploits the temporal locality of text, that is, whether its gain depends on having recently read related material.
Answering it requires streams that hold the same text in different orders, so that any difference between them is due to the order alone.
The \emph{main set} consists of 25 test books, each cut to its first 78 chunks (19{,}968 tokens), 1{,}950 chunks in total.
Its chunks are arranged in four orders of decreasing locality: book after book ($K=1$), as a book is normally read; groups of 5 books, interleaved chunk by chunk within each group ($K=5$); all 25 books interleaved chunk by chunk ($K=25$); and a single random permutation of all chunks (shuffled), in which no book is read in order.
Cutting the books short keeps the stream at about 500k tokens while leaving 25 books to compute standard errors over, and each book is still long enough to measure what the learner retains from up to about 10k tokens back within it.
Most results use the main streams, read in order and shuffled; the interleaved orders appear in Section~\ref{sec:levels}.

\paragraph{Long streams: reading further into a book.}
A main-set book ends after 20k tokens, so the main streams cannot show how the gain develops deep into a book.
The \emph{long} stream holds 5 test books of 100k tokens (390 chunks each) and the \emph{very long} stream 4 test books of 200k tokens (781 chunks each), both read book after book.
The long stream extends the locality comparison to longer books (Section~\ref{sec:levels}); the very long stream compares dynamic evaluation with a larger frozen model over a whole long book (Section~\ref{sec:long}) and tracks forgetting over the longest stream (Section~\ref{sec:forgetting}).
They hold fewer books than the main set, so their standard errors are wider.
All 5 long books and 2 of the 4 very long books also appear in the main set, cut there to their first 78 chunks.

\paragraph{The val-pick stream: tuning without the test books.}
Every learning rate is chosen before any test book is read, on a stream of its own, \emph{val-pick}: 10 PG-19 validation books of 78 chunks each, read book after book.
No reported result uses val-pick, and no learning rate is chosen on a test book.

\paragraph{Eviction streams: one book, then other text.}
To measure how fast other text displaces the memory of a book, the eviction experiment gives each of 20 main-set books its own short stream: the first half of the book followed by a varying amount of other books (Section~\ref{sec:snapshots}).

\paragraph{Held-out text.}
Not all text is read as a stream.
To measure forgetting we use two held-out sets that are never part of any stream and are therefore never trained on: 76 chunks of the detokenized WikiText-103 test split \cite{merity2017pointer}, outside the domain, and 6 other PG-19 validation books of 15 chunks each, inside it.
They are only scored, by frozen copies of the learner (Section~\ref{sec:snapshots}).

Pythia was trained on the Pile \cite{gao2020pile}, whose PG-19 component has 28{,}602 documents \cite{biderman2022datasheet}, the size of PG-19's training split.
The test books are therefore very likely absent from Pythia's training data, although the Pile's authors do not state this explicitly and we did not check for other copies of the books.

\subsection{Dynamic evaluation}

The learner reads a stream one chunk at a time, in two steps per chunk.
It first scores the chunk on its own, without earlier chunks in the context, so any benefit from earlier parts of the stream must come through the weights.
It then takes one update step on the chunk's mean loss and moves on to the next chunk.
Every token is therefore predicted before it is trained on.
We call the updated model the \emph{learner}, and compare it with the frozen pretrained model reading the same stream without updates.

We compare three update rules.
\emph{Plain SGD} uses no momentum or weight decay; \emph{Adam} \cite{kingma2015adam} starts each stream with a fresh optimizer state; and \emph{normalized SGD} moves every tensor by the same relative amount per step, $W \leftarrow W - \eta\, \lVert W\rVert\, g / \lVert g\rVert$.
All three update all parameters.
In addition, some plain-SGD runs on Pythia-14M update only part of the model: the output embedding, everything but the output embedding, the MLPs of all layers, the attention of all layers, or the MLP of a single layer.
Each combination of update rule, parameter subset and model size has its own learning rate, chosen as the value with the lowest mean loss under dynamic evaluation on the val-pick stream, from a grid of $1$ and $3$ times powers of ten.
The grid is extended until both neighbours of the best value have been tried, so every selected rate lies inside its grid.

\subsection{Snapshots}\label{sec:snapshots}

To see what the weights hold at a given point of a stream, we take \emph{snapshots}: the learner's weights are copied and the copy, kept frozen, scores text outside the stream, while the learner continues reading unaffected.
For forgetting, snapshots are taken every 40 chunks and scored on the held-out sets.
For eviction (Section~\ref{sec:eviction}), each of 20 main-set books A is split into a first half A1 (40 chunks) and a second half A2 (38 chunks), and gets a stream of its own, read from the pretrained weights: A1 followed by $I$ tokens of PG-19 validation books.
At the end of this stream a snapshot scores A2 and the same span C2 of a control book C that the learner never read.

\subsection{Metrics}

The \emph{gain} measures how much dynamic evaluation helps: the frozen loss minus the loss under dynamic evaluation on the same tokens of the stream, in nats/token, always against the model's own frozen loss.
To see where the gain comes from, \emph{distance bins} group tokens by how far back in the stream the same token id last occurred: in the same chunk (visible to attention), in an earlier chunk less than 1k, 1k to 10k, 10k to 100k or at least 100k tokens back, or never.
The 1000 most frequent ids are left out of the earlier-chunk bins, which are further split by whether the previous occurrence was in the same book or an earlier one.
\emph{Locality} is the part of the gain that requires the reading order: the gain on a stream in reading order minus the gain on the same chunks shuffled.
In the eviction experiment, the \emph{memory of A} is what a snapshot still knows about book A beyond general adaptation: its gain on A2 minus its gain on C2.
\emph{Forgetting} is the loss of general knowledge: a snapshot's loss on a held-out set minus that of the pretrained model, averaged over the snapshots in the second half of the stream, so that positive values mean knowledge lost.
Finally, the \emph{exchange rate} relates the two: a run's gain on the stream divided by its WikiText forgetting.

Means are taken over tokens.
Standard errors (SE) are computed over books, from per-book means or, when two runs read the same chunks, from paired per-book differences; books with fewer than 50 tokens in a bin are left out.
For forgetting, SE are computed over the WikiText chunks or the 6 held-out books.
A $\dagger$ marks a value under 2 SE, which we do not treat as a difference.

\section{Results}

\subsection{A memory beyond the window, and it is local}\label{sec:local}

If the updated weights hold a memory of the text, tokens seen recently in an earlier chunk should be predicted better, and the benefit should depend on the order of the chunks.
We bin tokens by the distance to their previous occurrence and compare reading in order with reading the same chunks shuffled.

With plain SGD at lr $10^{-4}$, Pythia-14M gains \gainInOrderAllPM{} nats/token over its frozen loss of \frozenLossMain{} (Table~\ref{tab:distance}).
The gain falls with distance: \gainInOrderOneKPM{} for rare tokens last seen less than 1k tokens back, \gainInOrderTenKPM{} between 1k and 10k, and \gainInOrderHundredKPM{} between 10k and 100k.
Tokens never seen before lose \gainInOrderNeverPM{}, and tokens repeated within their own chunk lose \gainInOrderSameChunkPM{}.
Within a book the gain grows from \posGainFirstPM{} in its first 1k tokens to \posGainLastPM{} in its last 1k, while the shuffled learner's gain stays between \posShuffledMin{} and \posShuffledMax{} (Figure~\ref{fig:distance}b).

Shuffling keeps \shuffledShareAll{} of the overall gain, but only \shuffledShareOneK{} less than 1k tokens back and \shuffledShareTenK{} between 1k and 10k (locality \localityOneKPM{} and \localityTenKPM{}).
Most of the overall gain is therefore adaptation to PG-19 text in general, and most of the long-range gain needs the order.

\paragraph{The current book.}
A token may be predicted better because it was seen recently, or because it belongs to the book being read.
Splitting the earlier-chunk bins by book separates the two (Table~\ref{tab:samebook}).
Between 1k and 10k tokens back, the locality is \localityTenKSamePM{} for tokens last seen in the same book and \localityTenKEarlierPM{} for tokens last seen in an earlier book.
Between 10k and 100k tokens back, same-book tokens keep \localityHundredKSamePM{} of locality and earlier-book tokens have none (\localityHundredKEarlierPM{}).
The memory is tied mostly to the current book, although distance still matters within it.

\paragraph{More than a count cache.}
A cache of recent token counts mixed into the frozen model ($p = 0.95\, p_\text{model} + 0.05\, p_\text{cache}$, counts halving every 1k tokens) is the simplest way to use the recent past.
It is the better copier less than 1k tokens back (\gainUnigramOneKPM{} against \gainInOrderOneK{}), but from 1k tokens on dynamic evaluation gains more (\gainInOrderTenK{} against \gainUnigramTenKPM{} between 1k and 10k; paired difference \inOrderMinusUnigramTenKPM{}), and \inOrderMinusUnigramAllPM{} more overall (Table~\ref{tab:distance}).

\subsection{Where the memory lives}\label{sec:where}

If the memory sits in particular weights, updating only those should keep it.
We update one part of Pythia-14M at a time, each part at its own learning rate (Table~\ref{tab:layers}).

Freezing the output embedding costs little (\minusFullNoOutputAllPM{} overall against all parameters).
The output embedding alone is a short-range cache: \gainOutputOneKPM{} less than 1k tokens back but \gainOutputTenKSamePM{} between 1k and 10k (same book), with the largest loss on never-seen tokens (\gainOutputNeverPM{}).
Attention alone keeps less of the long-range gain (\gainAttentionTenKSamePM{} between 1k and 10k, same book).
Updating only the MLPs (lr $3\times10^{-4}$) gains more than updating all parameters (lr $10^{-4}$): \gainMlpOneKPM{} against \gainInOrderOneK{} less than 1k tokens back (paired difference \minusFullMlpOneKPM{}) and \gainMlpAllPM{} against \gainInOrderAll{} overall (\minusFullMlpAllPM{}).

One layer's MLP alone keeps between \layerShareOneKMin{} and \layerShareOneKMax{} of the full learner's gain less than 1k tokens back, and between \layerShareTenKMin{} and \layerShareTenKMax{} between 1k and 10k (same book); every single layer is below the full learner there (Figure~\ref{fig:layers}a).
The strongest is layer \layerBest{} (\layerBestOneKPM{}, paired difference with all parameters \layerBestMinusFullPM{}), and the last layer is the weakest (\layerLastOneKPM{}).

\paragraph{MLPs only against all parameters.}
A larger gain could come from a stronger cache or from better general adaptation, and a stronger cache might cost more general knowledge.
We read the shuffled stream with both learners and probe both with snapshots (Table~\ref{tab:mlpfull}).
Updating only the MLPs gives more locality: \mvfMlpLocOneKPM{} against \mvfFullLocOneKPM{} less than 1k tokens back (paired difference \mvfDiffLocOneKPM{}) and \mvfMlpLocTenKPM{} against \mvfFullLocTenKPM{} between 1k and 10k, same book (\mvfDiffLocTenKPM{}).
Shuffled, it gains slightly less overall (\mvfDiffShuffledAllPM{}).
It also forgets more: WikiText forgetting is \mvfMlpWikiPM{} against \mvfFullWikiPM{} (paired \mvfDiffWikiPM{}), and the held-out books lose \mvfDiffBooksPM{} more (paired), although neither run's own value on them is beyond 2 SE.
Its exchange rate is lower: \mvfMlpExchange{} against \mvfFullExchange{} in order, \mvfMlpExchangeSh{} against \mvfFullExchangeSh{} shuffled.

The two learners use different learning rates, each its own val-pick (val-pick loss \valPickMlp{} for the MLPs at $3\times10^{-4}$ and \valPickAll{} for all parameters at $10^{-4}$).
All parameters at $3\times10^{-4}$ is already worse on val-pick (\valPickAllHigh{}).
A possible reason, not tested: with plain SGD at 14M, attention takes \shareAttnFourteen{} of the squared update norm and the MLPs \shareMlpFourteen{} (Section~\ref{sec:rules}), which may limit the step the full learner can use.

\subsection{Locality as a variable}\label{sec:levels}

A cache should help more the longer the input stays on the same material.
We read the same chunks with more and more books interleaved, and the long books in order (Figure~\ref{fig:layers}b).

With plain SGD on all parameters at lr $10^{-4}$, the gain falls at every step: \levelLongPM{} on the long books, \levelKOnePM{} with $K=1$, \levelKFivePM{} with $K=5$, \levelKTwentyFivePM{} with $K=25$ and \levelShuffledPM{} shuffled.
On the main set the paired drops are \dropKFivePM{} from $K=1$ to $K=5$, \dropKTwentyFivePM{} from $K=5$ to $K=25$ and \dropShuffledPM{} from $K=25$ to shuffled; interleaving only 5 books removes most of the in-order advantage.
The long books are other books than the main set, so the step from them to $K=1$ is not paired.

\subsection{Eviction}\label{sec:eviction}

If dynamic evaluation acts as a cache, reading other text should push a book out of memory.
We let the model read the first half of a book, then other books, and check with a frozen snapshot how well it still predicts the book's second half, compared with a book it never read (Figure~\ref{fig:eviction}).

With plain SGD on all parameters at lr $10^{-4}$, the memory of A is \memoryZeroPM{} right after A1.
It halves after about \evictHalfLife{} tokens of other books and then declines slowly: \memoryTenKPM{} after 10k tokens, \memoryHundredKPM{} after 100k and \memoryThreeHundredKPM{} after 300k.
The snapshots never gain on the control book (\gainCZeroPM{} right after A1, between \gainCMin{} and \gainCMax{} later), so the decline is the loss of A rather than general adaptation catching up.
The memory is mostly about tokens that occurred in A1: rare tokens of A2 whose id occurs in A1 carry \memoryRareInPM{} after A1, and other rare tokens \memoryRareNotInPM{}; the former halve after about \evictHalfLifeRare{} tokens.
A power law in $I$ fits the memory better than an exponential with a floor ($\chi^2$ \fitChiPower{} against \fitChiExp{}, with 4 degrees of freedom each), but the 7 points share the same 20 books, so this only ranks the two shapes.

\subsection{Forgetting}\label{sec:forgetting}

A cache should leave the rest of memory intact.
We score frozen snapshots of the learner on text it never reads: WikiText, outside the domain, and unseen PG-19 books, inside it (Table~\ref{tab:forgetting}).

With plain SGD at lr $10^{-4}$, Pythia-14M reading the main set in order forgets \forgetWikiKOnePM{} nats/token on WikiText (pretrained loss \frozenWiki{}), about \wikiOverGainKOne{} times its gain on the stream (exchange rate \exchangeKOne{}).
On the held-out PG-19 books it loses nothing (\forgetBooksKOnePM{}).
The shuffled learner forgets less on WikiText (\forgetWikiShuffledPM{}) and improves on the unseen books (\forgetBooksShuffledPM{}): the part of the gain that survives shuffling is adaptation to PG-19 text, and it carries over to unseen books.
Reading in order forgets more than shuffled on both sets (shuffled $-$ in order: \shMinusKOneWikiPM{} on WikiText, \shMinusKOneBooksPM{} on the books), at about the same exchange rate (\exchangeKOne{} and \exchangeShuffled{}).
On the very long set (800k tokens), WikiText forgetting averages \veryLongWikiBookOne{} over the snapshots taken in the first book and \veryLongWikiBookTwo{}, \veryLongWikiBookThree{} and \veryLongWikiBookFour{} in the next three: it levels off after the first book.
There the held-out books also lose a little (\forgetBooksVeryLongPM{}).

\subsection{Update rules and model size}\label{sec:rules}

With plain SGD, a learning rate small enough for some weights may be too small for others, and the balance changes with model size.
We log the size of each update and compare three update rules at three sizes, each with its own learning rate (Table~\ref{tab:rules}, Figure~\ref{fig:rules}).

Over the first 40 chunks, plain SGD at each size's pick moves the MLP weights by \relMlpFourteen{} of their norm per step at 14M, \relMlpThirtyOne{} at 31M and \relMlpSeventy{} at 70M, about \mlpStepRatio{} times less at 70M than at 14M; at 70M attention takes \shareAttnSeventy{} of the squared update norm and the MLPs \shareMlpSeventy{}.
With plain SGD, Pythia-70M gains \rGainSgdSeventyPM{} and has almost no locality (\rLocOneKSgdSeventyPM{} less than 1k tokens back).
Normalized SGD more than doubles 70M's gain (\rGainNsgdSeventyPM{}; paired difference \nsgdMinusSgdGainSeventyPM{}) and gives it locality (\rLocOneKNsgdSeventyPM{}), still far less than at 14M and 31M under the same rule (\rLocOneKNsgdFourteenPM{} and \rLocOneKNsgdThirtyOnePM{}), which are the largest of any rule.
Adam has no cache at any size: its locality less than 1k tokens back is \rLocOneKAdamFourteenPM{} at 14M, \rLocOneKAdamThirtyOnePM{} at 31M and \rLocOneKAdamSeventyPM{} at 70M.

From 14M to 31M, plain SGD's locality does not change beyond noise (31M $-$ 14M: \locDiffThirtyOneFourteenOneKPM{} less than 1k tokens back, \locDiffThirtyOneFourteenAllPM{} overall; SE unpaired across models); it falls at 70M under every rule.
The smaller model does not pay more general knowledge per nat of gain: the exchange rate at 14M is \rExchangeSgdFourteen{}, \rExchangeAdamFourteen{} and \rExchangeNsgdFourteen{} (plain SGD, Adam, normalized SGD), against \rExchangeSgdThirtyOne{}, \rExchangeAdamThirtyOne{} and \rExchangeNsgdThirtyOne{} at 31M.
At 70M it is \rExchangeSgdSeventy{}, \rExchangeAdamSeventy{} and \rExchangeNsgdSeventy{}, with much smaller gains.

\subsection{A trade-off between cache and general knowledge}\label{sec:tradeoff}

If the cache and general knowledge share the same weights, filling one should erode the other.
We place every run with snapshots on two axes: how much cache it has (locality less than 1k tokens back) and how much WikiText it forgets (Figure~\ref{fig:tradeoff}).

Within 14M the order is the same on both axes: Adam (\rLocOneKAdamFourteen{}, \rWikiAdamFourteen{}), plain SGD on all parameters (\rLocOneKSgdFourteen{}, \rWikiSgdFourteen{}), plain SGD on the MLPs only (\mvfMlpLocOneK{}, \mvfMlpWiki{}) and normalized SGD (\rLocOneKNsgdFourteen{}, \rWikiNsgdFourteen{}).
Within 31M the same holds for Adam, plain SGD and normalized SGD.
At 70M plain SGD and normalized SGD follow it, but Adam forgets more than both (\rWikiAdamSeventyPM{}) with negative locality.
Across sizes the points do not lie on one curve: at 70M every rule forgets far less for a given locality.
With ten points, one seed and one model family, this is a consistent ordering within the 14M and 31M settings we tried, not a law, and it does not hold for Adam at 70M.

\section{Discussion}

\paragraph{Does dynamic evaluation help more with locality than with random input?}
Yes: the gain from more than 1k tokens back mostly disappears when the chunks are shuffled, and the overall gain falls at every step from long books to shuffled chunks (Sections~\ref{sec:local} and~\ref{sec:levels}).

\paragraph{Does it evict like a cache?}
Yes for the memory of a specific book: it halves after a few thousand tokens of other books, with a long tail (Section~\ref{sec:eviction}).
Unlike a cache, filling it overwrites general knowledge outside the domain: WikiText forgetting is about twice the gain on the stream, and within 14M and 31M a stronger cache forgets more (Sections~\ref{sec:forgetting} and~\ref{sec:tradeoff}).

\paragraph{Is the effect larger in small models?}
Not between 14M and 31M: locality does not change beyond noise, and 14M does not pay more forgetting per nat of gain.
70M has less cache, but how much depends on the update rule and the step size it allows (Section~\ref{sec:rules}).

\paragraph{Is there a knob?}
Partly: the parameter subset and the update rule move the size of the cache, but within 14M and 31M every setting we tried moves cache and forgetting together (Section~\ref{sec:tradeoff}).
No knob tested here separates the cache from general knowledge.

\paragraph{Can a small model with dynamic evaluation replace a larger one?}
Not at these sizes: on long books dynamic evaluation is worth about half the step from 14M to 31M, but 31M gains as much from it (Section~\ref{sec:long}).
Baselines with the full context window and with matched compute are still missing.

\paragraph{Does it resemble human memory?}
Only suggestively, and we did not test it directly.
Most of a book's memory is on the specific tokens seen (\memoryRareIn{} for rare tokens of A1, against \memoryRareNotIn{} for other rare tokens), which resembles episodic memory, while the gain that survives shuffling transfers to unseen books, which resembles semantic memory.
Eviction is fast at first and slow later, closer to a power law than to an exponential.

\section{Limitations}

\begin{itemize}
\item \textbf{One seed.} Error bars are across books, not across models or runs.
\item \textbf{Three sizes of one family.} Pythia-14M, 31M and 70M only.
\item \textbf{One kind of data.} PG-19 books only; WikiText is the only out-of-domain text, and forgetting is measured on 76 WikiText chunks and 6 books.
\item \textbf{No full-context baseline.} Chunks of 256 tokens are scored without earlier context; a model with its full context window would see more of the recent past through attention.
\item \textbf{Learning rates.} Rates are picked on mean validation loss, not on locality, and different subsets and sizes use different rates, so comparisons across them mix in the rate.
\item \textbf{Wall time is not compute.} We did not measure compute; dynamic-evaluation runs update after every chunk, frozen runs do not.
\item \textbf{Overlapping sets.} All 5 long books and 2 of the 4 very long books are also in the main set.
\end{itemize}

\section{Future work}\label{sec:future}

\begin{itemize}
\item A separate fast cache part on top of a frozen or slowly learning model, with a fallback to the frozen model when the cache does not help.
\item Capacity: many books interleaved at once, and the size of the adapted part against the eviction half-life.
\item Why Adam removes the cache: ablate its momentum and its per-weight normalization.
\item Baselines with the full context window and with matched compute.
\item More seeds (PolyPythias \cite{vanderwal2025polypythias}) and larger models.
\item Direct memory tests: savings on re-reading, interference between similar books, spacing, and planted facts.
\end{itemize}

\section{Conclusion}

Small language models are cheaper to run and easier to deploy, but their limited capacity restricts how much knowledge and context they can retain.
We started from the observation that what a model reads has temporal locality, so that a small model whose weights cached its current context, instead of permanently holding everything it might need, could perform on that context closer to a larger one.
Dynamic evaluation is a natural candidate for such a cache, provided that its forgetting, usually seen as the price of learning at inference time, acts as eviction: a model that forgets old material as it learns new material might hold the recent context in its weights beyond the attention window.
We asked whether this behaviour arises on its own in a small transformer that takes plain gradient steps as it reads, and tested the three properties a cache should have.

The first two hold.
The benefit of dynamic evaluation depends on locality: most of the gain on tokens last seen in an earlier chunk requires the text to be read in order (only \shuffledShareOneK{} of the gain less than 1k tokens back survives shuffling), the memory is tied to the book being read, and the gain shrinks steadily as books are interleaved.
Other text evicts this memory, halving it after about \evictHalfLife{} tokens of other books, with a long tail.
The memory sits mostly in the MLPs.

The third property holds only in part.
Knowledge of the same domain is largely preserved, but the cache shares its weights with general knowledge, and filling it costs knowledge outside the domain: about \wikiOverGainKOne{} nats of WikiText loss per nat gained.
The update rule and the set of weights being updated change how much cache a model gets, but within 14M and 31M every setting we tried moved cache and forgetting together.

A standard transformer thus has a cache in its weights, but not a clean one: the useful forgetting that evicts old context comes bundled with the harmful forgetting of general knowledge.
Even so, the cache already matters at this scale: on long books, a 14M-parameter model with dynamic evaluation closes \gapClosedFourteen{} of the gap to a frozen model about twice its size, and the cache behaves in the same way at both sizes.
Separating useful from harmful forgetting, for instance with a dedicated fast part of the network, could strengthen the cache and make better use of temporal locality, moving towards small models that perform on the context at hand like larger ones.
